# 书屋小闯关验收示例

五道题的 Canvas2D 示例：菜单 → 答题 → 正确/错误反馈 → 下一题 → 结算 → 重玩。支持暂停、切后台后手动恢复、取消触摸和最高分本地保存。角色目前为代码绘制的占位图，默认无音频文件；未调用任何外部生成服务。

## 运行与素材整合

将本目录导入微信开发者工具，填写自己的小游戏 AppID。通过 `examples/quiz-handoff.json` 生成素材任务，人工审查后用 ai-handoff import 导入到本目录的 ai-assets/v1，再把 resources.js 的导出改为 `require('./ai-assets/v1/index')`。菜单背景和 mascot 图片会自动加载；缺失或加载失败保留绘制回退。清单中的 correct-sfx 会接入答对音效，支持菜单静音与切后台停止；加载失败回退为无声音。背景图需符合菜单比例，具体显示效果仍须截图检查。

## 视觉基线

暖纸色 #f6f2e7、深绿色文字 #233f35、主按钮 #255d49；角色形状圆润，背景让位于题目与控件。主操作触摸区域高 52 逻辑像素，字号 16–27，界面文字由代码绘制。正式风格确认请填写 references/art-direction-template.md，不将本示例的配色当成所有项目要求。

## 手工验收

- 320×568 与 414×896：菜单、答题、两种反馈、暂停和结算都截屏；记录安全区和胶囊位置。
- 连续答对五题得到 5 分；答错不加分；反馈期间连点不重复计分。
- 答题与反馈时切后台，恢复停在暂停页，继续后保持题号和得分。
- 滑出按钮或取消触摸不触发操作；重玩清空本局分数，最高分保留。
- 导入图片后检查实际尺寸下的辨认度、透明边缘和风格一致性；模拟加载失败检查回退。
- 小屏长题目和选项不裁切，角色与控件不变形，截图符合视觉 QA 清单。

## 当前证据

自动验证覆盖模型、模拟触摸流程、绘制调用及代表屏幕的控件边界。没有微信开发者工具运行、实际截图或真机证据，视觉状态为待验。它是可运行工程的测试样例，不代表已完成外部 AI 美术生产或发布验收。
